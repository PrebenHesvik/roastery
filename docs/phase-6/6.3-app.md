## 1. Context

6.2 fixed the shape on paper: 41 modules in 8 layers (ADR 0001), the ports and their adapters, and contract B as typed signatures in `architecture.md` §5. 6.3 writes the code so that:

- the unit and contract suites pass on the memory store and on sqlite;
- `architecture.py` passes (direction, unplaced), with `AWAITING` holding exactly the four api modules;
- the teachability test passes (no module state, no wall clock, no unseeded random, sorted listings, 72 characters);
- `packages/shop/tests/test_contract_b.py` renders the surface of C27 and matches the committed `contract_b.txt`, which matches §5's block.

Contract B is a candidate here; 6.4 proves it against the frozen week and freezes it (tag `shop 0.1.0`).

The seams follow the `codebase-design` vocabulary. A port is a real seam only where two adapters stand at it: memory and sqlite; the API and the simulator; `SequentialIds` and `ScriptedIds`; `FakeFeed` and the simulator's feed; `FakeProvider` and `ProviderPayments`. The cache is a concrete class (one adapter, C31). Nothing is built that fails the deletion test.

Tests are written for the critical pieces only, where a quiet mistake would reach the data or a page (the owner's rule): no test that a frozen dataclass keeps its fields, that a getter returns what was set, that a repr looks a certain way, that a constant equals itself, or that an import works.
