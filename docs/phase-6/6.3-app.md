## 1. Context

6.2 fixed the shape on paper: 41 modules in 8 layers (ADR 0001), the ports and their adapters, and contract B as typed signatures in `architecture.md` §5. 6.3 writes the code so that:

- the unit and contract suites pass on the memory store and on sqlite;
- `architecture.py` passes (direction, unplaced), with `AWAITING` holding exactly the four api modules;
- the teachability test passes (no module state, no wall clock, no unseeded random, sorted listings, 72 characters);
- `packages/shop/tests/test_contract_b.py` renders the surface of C27 and matches the committed `contract_b.txt`, which matches §5's block.

Contract B is a candidate here; 6.4 proves it against the frozen week and freezes it (tag `shop 0.1.0`).

The seams follow the `codebase-design` vocabulary. A port is a real seam only where two adapters stand at it: memory and sqlite; the API and the simulator; `SequentialIds` and `ScriptedIds`; `FakeFeed` and the simulator's feed; `FakeProvider` and `ProviderPayments`. The cache is a concrete class (one adapter, C31). Nothing is built that fails the deletion test.

Tests are written for the critical pieces only, where a quiet mistake would reach the data or a page (the owner's rule): no test that a frozen dataclass keeps its fields, that a getter returns what was set, that a repr looks a certain way, that a constant equals itself, or that an import works.

## 2. Decisions for this step

## 3. The units

Order: **U0 → U1 → U2 ‖ U4 → U3 → U5a → U5b ‖ U6 → U7 → U8 → U9 → U10 → U11 → U12 → U13**. One opus job at a time: U2 and U3 run in sequence, U4 (sonnet) beside either. U5b and U6 (both sonnet) may run together. Agents never commit; after each unit the lead runs `uv run ruff check`, `uv run ruff format --check` and `uv run python -m pytest packages/shop`, then commits that unit's paths.

**Every brief carries** the five parts of CLAUDE.md and this block:

- Read by path: CLAUDE.md; `docs/architecture.md` §1, §2, the §3 rows of the unit's modules, and the unit's §5 line range; the unit's ADRs; this file's §2.
- Teachability: no module state (constants are `Final` tuples, frozensets or `MappingProxyType`; registries and buses are built in `wire`); no `datetime.now`, `time.time`, unseeded `random` or `uuid4`; listings sorted (`ORDER BY` on every multi-row `SELECT`, `sorted` in memory); `from __future__ import annotations` in every module; single quotes, double-quoted docstrings; `ruff format` at 72 (tests too); `import datetime as dt`.
- Signatures: the unit's slice of §5 copied exactly (names, keyword-only markers, defaults, annotations as written). A part that §3 names and the unit names differently is listed in the reply, so the lead fixes §3 in the same commit (ADR 0015).
- Every shell command starts with `cd /c/dev/roastery &&` (the session's default directory is another repository).
- Fixture ids are grepped from `dataset.sql` and `contract.md` (the table below), never reconstructed.
- Done-when always includes: ruff clean; `test_architecture.py` passes with `AWAITING` reduced by exactly the unit's modules; the unit's tests pass on both stores where a store is involved.
- Not to touch: any module outside the unit; `docs/`; `packages/spec`; `packages/sim`.
- Reply: a short summary, the files changed, the test result, the §3 parts named differently, and every point the ADRs left open that the agent decided (the lead makes each an A-row or reverts it).
